# Заметки по разработке Talkora

- При локальных офлайн-изменениях сохраняйте `base`, `version` и признак `pending` вместе с состоянием конкретного пользователя. После входа в тот же аккаунт объединяйте сохранённые изменения с серверным состоянием; иначе офлайн-прогресс исчезнет.
- При конфликте версии объединяйте учебные события по устойчивому `id`, а не складывайте два значения XP целиком: ответ сервера мог потеряться уже после записи события.
- При слиянии списков слов учитывайте удаления с обеих сторон. Простое объединение массивов возвращает удалённые пользователем слова.
- Android WebView с упакованным `dist` не получает API по относительному `/api`. Указывайте `VITE_API_URL` с общим HTTPS API при сборке Android и добавляйте `https://localhost` к `APP_ORIGIN` сервера. Для cookie между WebView и API нужны `SameSite=None; Secure`, credentialed CORS и разрешение third-party cookies в WebView; HTTP-тесты этих заголовков не заменяют испытания входа и синхронизации на устройстве.
- Готовые тематические наборы не называйте ИИ-генерацией. Browser Speech Synthesis с предпочтением `en-GB` не означает наличие качественной британской записи.
- PDF.js сначала читает текстовый слой PDF; для страниц без текста и изображений Tesseract.js распознаёт английский/русский на устройстве. Никогда не сохраняйте сырой OCR без редактируемого черновика и подтверждения слов/переводов. OCR-движок и языки хранятся среди статических ресурсов Talkora; Android APK включает их, а веб-клиент получает и кеширует при первом использовании. Android packaging требует несжатые файлы `.traineddata`, потому что AAPT распаковывает `.gz` и меняет путь.
- Серверная лига считает по UTC-неделям основные уроки, мини-тесты, онлайн-сессии личных слов и шесть готовых тем с проверенными первыми ответами; точность и награду пересчитывает сервер. Стартовый тест тоже проверяется по каталогу, не даёт XP и может только сохранить или повысить стартовую арену; `profile.level` нельзя менять отдельно от его proof. Локальные сессии без proof дают общий XP, но не очки лиги. Динамическая сессия привязана к аккаунту и хранится 30 дней. Тематический вариант выбирается сервером по сохранённым возрасту и уровню из сгенерированного каталога. Поскольку клиент получает ответы для обратной связи, до публичного соревнования всё ещё нужны защита от автоматизации и ограничения частоты.
- Восстановление серии и расход кристаллов идут через `POST /api/streak/restore`. Не разрешайте создавать такие события через обычный `PUT /api/state`: иначе клиент сможет сам назначить цену или вернуть бесплатную попытку.
- При конфликте двух устройств пересчитывайте серию от последнего серверного дня по новым локальным событиям занятий. `Math.max(local.streak, remote.streak)` оставляет невозможную серию, если один клиент пропустил день, и сервер отклонит повторную синхронизацию.
