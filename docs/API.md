# Talkora — локальный API прототипа

Сервер использует Node.js 24 и встроенные `node:http` / `node:sqlite`, без внешних серверных зависимостей. Он хранит реальные аккаунты, приватный прогресс и обращения в SQLite. Это работающий сервер прототипа, а не готовая инфраструктура публичного образовательного сервиса.

## Запуск

```powershell
node server/index.mjs
```

По умолчанию сервер слушает `http://127.0.0.1:3001`, хранит данные в `data/talkora.sqlite` и отдаёт собранный интерфейс из `dist/`. После сборки интерфейса сайт и API работают с одного origin. Для разработки прокси `/api` должен сохранять исходный `Host` (`changeOrigin: false`).

Переменные окружения:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3001` | Порт HTTP |
| `HOST` | `127.0.0.1` | Интерфейс сервера |
| `DB_PATH` | `data/talkora.sqlite` от корня проекта | Файл SQLite |
| `APP_ORIGIN` | пусто | Точные доверенные origins через запятую, например `https://talkora.example` |

Локальные `localhost` и `127.0.0.1` разрешены при точном совпадении `Origin` и `Host`, включая порт. Для любого внешнего домена нужно явно задать `APP_ORIGIN`. Заголовки `X-Forwarded-*` не считаются доверенными автоматически. Это также исключает доверие к произвольному внешнему `Host` при DNS rebinding.

Для публикации необходим HTTPS reverse proxy. Если запрос приходит от настроенного HTTPS origin, сессионная cookie получает `Secure`. Для сайта удобен общий origin с API. Упакованный Android WebView работает с `https://localhost`: при `APP_ORIGIN=https://talkora.example,https://localhost` и сборке с `VITE_API_URL=https://api.example.com` сервер разрешает credentialed CORS только перечисленным origins и выдаёт Android-клиенту cross-site cookie `SameSite=None; Secure`. Android-клиент явно включает приём сторонних cookies в своём WebView. Эти настройки проверены HTTP-тестом, но реальный вход и повторный запуск на Android-устройстве ещё нужно проверить.

## Общие правила

- Формат — JSON, UTF-8. Максимальное тело запроса: 1 МиБ.
- Все изменяющие запросы требуют `Content-Type: application/json` и доверенный `Origin`. При отсутствии `Origin` допускается совпадающий `Referer`.
- Сессия передаётся автоматически cookie `talkora_session`: `HttpOnly`, срок 30 дней. Для сайта применяется `SameSite=Lax`; для явно разрешённого стороннего HTTPS origin — `SameSite=None; Secure`.
- Клиент не хранит bearer token в localStorage. В SQLite записывается SHA-256 хеш непрозрачного случайного токена сессии.
- Пароли: 8–128 символов; scrypt, индивидуальная случайная соль, `N=32768`, `r=8`, `p=1`.
- Никнейм: 3–24 буквы, цифры, дефис или подчёркивание. Настоящее имя не требуется.
- На вход, регистрацию и проверку пароля удаления действует общий предел 20 попыток с IP за 15 минут. При превышении: `429` и `Retry-After`.
- Ответы API используют `Cache-Control: no-store`.
- Ошибки: `{ "error": "Понятное сообщение" }`; `400` — валидация, `401` — сессия/пароль, `403` — origin, `409` — конфликт, `413` — размер, `429` — лимит.
- Идентификатор владельца берётся исключительно из сессии. При передаче `userId` в изменяющих запросах состояния, поддержки, выхода или удаления он обязан совпасть с владельцем сессии; иначе `403` без возврата чужого состояния. Это защищает от сохранения очереди старого аккаунта после смены cookie в другой вкладке.

## Методы

| Метод | Путь | Тело | Результат |
| --- | --- | --- | --- |
| GET | `/api/health` | — | `{ok:true, service:"Talkora", mode:"prototype"}` |
| GET | `/api/session` | — | `{user:null}` или `{user,state,version}` |
| POST | `/api/auth/register` | `{email,password,nickname}` | `201 {user,state,version}` + cookie |
| POST | `/api/auth/login` | `{email,password}` | `{user,state,version}` + новая cookie |
| POST | `/api/auth/logout` | `{userId?}` | `{ok:true}`, удаление текущей серверной сессии и cookie |
| GET | `/api/state` | — | `{state,version}` текущего пользователя |
| GET | `/api/league` | — | Текущая недельная группа, места, очки и итог прошлой недели |
| POST | `/api/practice/words` | `{words,minutes,userId?}` | `201 {sessionId,activityId,title,exercises}` для проверяемой тренировки личных слов |
| POST | `/api/practice/topic` | `{topicId,minutes,userId?}` | `201 {sessionId,activityId,title,description,words,exercises}` для опубликованной темы |
| PUT | `/api/state` | `{state,version,userId?}` | `{state,version}` с увеличением версии на 1 |
| POST | `/api/streak/restore` | `{day,userId?}` | `{state,version,cost}`; сервер восстанавливает серию и списывает кристаллы |
| POST | `/api/support` | `{category,message,technical?,userId?}` | `201 {report:{id,category,message,createdAt}}` |
| DELETE | `/api/account` | `{password,userId?}` | `{ok:true}`, полное логическое удаление аккаунта |

`user` содержит только `{id,email,nickname}`. Пароль, его хеш и сессионный токен в JSON не возвращаются. Email нормализуется к нижнему регистру; почта и никнейм должны быть уникальны.

Обращение в поддержку сохраняется в приватной таблице `support_reports`. Сообщение: 5–5000 символов; категория: до 80; технические данные — JSON-объект до 8000 символов. Отправки email и рабочего места операторов в этом API пока нет. Форма должна честно показывать сохранение обращения, не обещать получение ответа команды.

Удаление аккаунта требует текущий пароль. Внешние ключи с `ON DELETE CASCADE` удаляют состояние, все сессии пользователя и обращения. Клиент дополнительно обязан удалить собственный локальный кеш и очередь офлайн-синхронизации этого аккаунта. Резервные копии, если будут добавлены при развёртывании, требуют отдельной политики удаления; прототип их не создаёт.

## Состояние и синхронизация

Начальное состояние:

```json
{
  "profile": {
    "age": "25+",
    "goals": ["travel"],
    "avatar": "leaf",
    "onboarded": false,
    "level": "A1",
    "locale": "ru",
    "reminderEnabled": false,
    "reminderTime": "19:00",
    "reminderDays": [1, 2, 3, 4, 5]
  },
  "progress": {
    "xp": 0,
    "coins": 0,
    "streak": 0,
    "bestStreak": 0,
    "lastStudyDate": null,
    "streakRestoredDate": null,
    "completedLessons": [],
    "passedArenas": [],
    "dailyBonusDate": null,
    "freeRestoreUsed": false,
    "placementArena": 0
  },
  "words": [],
  "history": [],
  "reports": []
}
```

Возрастные идентификаторы: `0-14`, `15-24`, `25+`. Языки интерфейса: `ru`, `en`. Цели: `travel`, `work`, `study`, `social`, `exams`, `personal`; совместимые альтернативы `communication`, `self` также принимаются. Дни недели: `0` = воскресенье, `6` = суббота. Даты обучения и бонуса: `YYYY-MM-DD` или `null`.

Верхнеуровневые `words`, `history`, `reports` — массивы объектов (максимум 10000 / 5000 / 1000 записей). Дополнительные JSON-поля сохраняются, но структура ограничена 12 уровнями вложенности, 30000 узлами и 16000 символами на строку. Обязательные поля валидируются; отрицательные XP, неизвестные уровни и некорректные настройки не принимаются. При обновлении состояния старые события истории нельзя удалить, изменить или повторить; прирост XP и кристаллов должен точно совпадать с новыми событиями. Серия, дата последнего занятия и лучшая серия сверяются с датами новых учебных событий; прямое изменение этих счётчиков без занятия отклоняется. Учебное событие может принести не более 50 XP и 10 кристаллов.

Событие основного урока или мини-теста содержит `proof: {contentId, activityId, responses}`, где `responses` — первые ответы пользователя в порядке опубликованного набора упражнений. Сервер сверяет идентификаторы и ответы с `server/course.generated.json`, пересчитывает точность, результат мини-теста, название, XP и кристаллы. За первое завершение урока начисляется 30 XP, за успешный мини-тест — 50 XP, за неуспешную попытку и повторное прохождение — не более 10 XP. Новую завершённую активность и пройденную арену нельзя добавить без подходящего проверенного события.

`POST /api/practice/words` принимает от 2 до 12 подтверждённых пользователем пар, выбирает смешанный набор на 5, 10 или 15 минут и сохраняет серверную сессию на 30 дней. Результат содержит `proof: {sessionId, activityId, responses}`. Сессия привязана к аккаунту: сервер отклоняет чужой идентификатор, изменённый порядок, неизвестное упражнение, неверную точность или награду. Успешно проверенное первое прохождение даёт 30 XP и 5 кристаллов. Если сеть недоступна, клиент использует локальный генератор; результат сохраняется в общем прогрессе, но не подтверждается для лиги.

`POST /api/practice/topic` принимает идентификатор одной из шести редакционных тем. Сервер читает сохранённые возраст и CEFR-уровень, выбирает детский или общий и начальный или расширенный вариант из `course.generated.json`, затем фиксирует упражнения в такой же 30-дневной сессии. Клиент не передаёт ответы или выбранный вариант. Неизвестная тема отклоняется. После завершения сервер проверяет первые ответы, точность, заголовок и 30 XP; изученные в сессии слова клиент добавляет в приватное повторение. Это проверка опубликованного набора, а не генерация произвольной темы с ИИ.

`POST /api/streak/restore` — отдельная онлайн-операция. При одном пропущенном календарном дне сервер проверяет предыдущую дату занятия и выбранный локальный день, сохраняет событие восстановления и возвращает обновлённую версию состояния. Первое восстановление стоит 0, последующие — 20 кристаллов. Повторный запрос за тот же день отклоняется. Обычный `PUT /api/state` не может создавать события восстановления или списывать кристаллы. После восстановления пользователь должен пройти урок сегодня: само восстановление не считается занятием. Клиентские часовые пояса пока не сохраняются отдельным полем; сервер допускает локальный день, отличающийся от текущей UTC-даты на один день.

Лига хранит отдельные группы до 12 участников и счёт по UTC-неделям с понедельника. В рейтинг попадают события основных уроков, мини-тестов, онлайн-тренировок личных слов и шести готовых тем, для которых сервер успешно проверил `proof`; локальные сессии без доказательства и старые события дают общий XP, но не очки лиги. Событие попадает в неделю по времени приёма сервером, поэтому офлайн-занятие, отправленное после смены недели, учитывается в новой неделе. Группы подбираются по ступени и диапазону проверенной активности предыдущей недели. В группе от трёх участников верхние места повышаются, нижние понижаются; на первой ступени понижения нет. API возвращает только ник, аватар, место и очки соперника — без email и личных слов. Ответы необходимы работающему клиенту для проверки и объяснений, поэтому эта схема подтверждает структуру результата и награду, но сама по себе не защищает публичную лигу от автоматизации.

Клиент получает `version` при входе и чтении состояния. При сохранении передаёт ту версию, на которой основаны изменения, и `userId` владельца снимка, чтобы смена cookie в другой вкладке не записала старый снимок в новый аккаунт. SQL обновляет запись только при совпадении версии. Если другой клиент уже сохранил изменения, сервер возвращает:

```json
{
  "error": "Прогресс изменился на другом устройстве. Обновите данные перед сохранением.",
  "state": { "...": "актуальное серверное состояние" },
  "version": 4
}
```

Статус — `409`; старый запрос не перезаписывает прогресс. Клиент должен явно разрешить конфликт или объединить данные по устойчивым идентификаторам. Нельзя автоматически отправлять устаревший снимок с новой версией: это потеряет изменения с другого устройства. Сервер не выполняет CRDT-слияние и не обеспечивает фоновую доставку офлайн-очереди самостоятельно.

## Проверка

```powershell
node --test tests/server.test.mjs
```

Тесты выполняют реальные HTTP-запросы к временному серверу и реальной временной SQLite: регистрация/вход/выход, приватность аккаунтов, конфликт версий, проверка журнала очков, недельные группы и смена недели, валидация, защита origin, удаление с каскадом, сохранение после перезапуска, хеширование токенов, ограничение попыток и отдача SPA.

## Что требуется до публичного запуска

1. Подтверждение email, восстановление пароля, реальные Google/Apple OAuth credentials и проверка входа Android.
2. Расширение авторитетной проверки на будущие AI-задания, защита от автоматизации, ограничения частоты и анализ подозрительных результатов. Основной курс, онлайн-сессии личных слов и шесть готовых тем уже проверяются, но клиенту всё равно доступны ответы для показа обратной связи.
3. Полноценные миграции БД, резервное копирование, удаление из резервных копий, мониторинг, централизованные лимиты за reverse proxy и управление секретами.
4. Проверенные политики работы с детскими аккаунтами, обработкой персональных данных, регистрацией и обращениями.
5. Редакторская публикация контента, роли администраторов, журнал действий, настоящая ИИ-генерация и независимая проверка заданий.
6. Синхронизация при конфликтующих офлайн-изменениях и интеграционные проверки на нескольких физических устройствах.

API не выдаёт шаблонные задания за ИИ и не содержит открытого административного endpoint.
